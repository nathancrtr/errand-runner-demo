Prompt 1 · the tools

What an agent is

An agent is a model with a short list of commands it may run, called in a loop. On a typical Friday this one goes around six to a dozen times.

Prompt 1 · the tools

It only knows what you hand it

  • It hasn't seen my city's website and doesn't know what I care about unless a file tells it. Where the agendas are published is written in watch.toml. What matters to me is a paragraph in PROFILE.md.
  • Too much hurts as well. The first version handed it 100 KB of agenda from one command, more than it gets to see at once. A short listing and a way to open one item fixed that.
Prompt 2 · the policy

Not too much model

  • Use the best model for the job, then turn it down where you can. More thinking means a longer wait and a bigger bill, and past some point the answer stops getting better.
  • I started this session at medium effort on purpose. The quiet stretch in Prompt 1 was the model planning; how long that takes depends on how hard I ask it to think.
Prompt 2 · the policy

Help the model make itself obsolete

  • If a step should come out the same every time, ask the model to write it as code.
  • Fetching agendas, reading PDFs, measuring distance from home, and writing the calendar file are all plain Python. The model wrote it once, and it costs nothing to run.
  • What's left for the model on Friday is the part that takes judgment. Which of 83 agenda items matter to me?
Prompt 2 · the policy

When all you have is an LLM......everything looks like a nail.

  • Give a frontier model enough time and money and it can do nearly anything, but that doesn't mean it should.
  • Adding the same meeting to the calendar twice does nothing. Code checks an ID in the calendar file, so the model doesn't have to remember what it added last week.

If it has to be right every time, it should be code.

Prompt 3 · the leash and the clock

Rules that must hold belong in code

  • PROFILE.md asks the model to care about my neighborhood. Asking works most of the time, and for matters of taste that's good enough.
  • In rehearsal, the run-time model had permission to run four commands, and it could still have read other files on my computer, including the one with my home coordinates.
  • The fix was a few lines of code that refuse any command other than the errand's own. When I tested it by asking it to list my home folder or read that file, the check refused.
Prompt 3 · the leash and the clock

Say what done looks like, then check

  • The specification for this project is one sentence. The prompts are that sentence said three times, asking for a little more each time.
  • I don't read every line it writes. I run it and look at what it did, starting with which agenda items it opened and which it skipped.
  • Worth checking: did it find the real data source or make one up? When a page is blocked, does it say so and move on?
Prompt 3 · the leash and the clock

Find your own errand

  • Something you check by hand every week.
  • A public place where the information shows up.
  • A paragraph about what matters to you.
  • A place you'd like to hear about it, like your calendar or your inbox.
